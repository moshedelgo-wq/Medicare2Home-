MEDICARE2HOME — אבטחה לפני עלייה לאוויר
========================================

מה כבר הוכן בחבילה:
1. HTTPS forced redirect — קבצים מוכנים ל-Apache / Nginx / IIS.
2. HSTS — לאחר חיבור HTTPS תקין.
3. Content-Security-Policy — חסימת scripts/frames/resources שאינם נדרשים.
4. X-Content-Type-Options: nosniff.
5. Clickjacking protection — frame-ancestors 'none' + X-Frame-Options DENY.
6. Referrer-Policy.
7. Permissions-Policy — חסימת מצלמה, מיקרופון, מיקום, תשלומים ו-USB שאינם בשימוש.
8. Cross-Origin-Opener-Policy / Cross-Origin-Resource-Policy.
9. Directory listing disabled ב-Apache/IIS ודוגמא ל-Nginx.
10. security.txt ב-/.well-known/.
11. אין באתר מנגנון העלאת קבצים לשרת. הטפסים הנוכחיים פותחים תוכנת דוא"ל ואינם שומרים מידע באתר.

חובה לבצע על שרת הייצור:
- להתקין תעודת TLS/SSL תקפה ולבדוק שכל HTTP עובר ל-HTTPS.
- לבחור רק קובץ הגדרות אחד לפי ספק האחסון; אין להעלות את כל קבצי השרת בלי להבין מה הספק תומך.
- לבדוק Security Headers לאחר העלייה.
- להפעיל MFA בחשבון הדומיין, DNS, ספק האחסון ו-Cloudflare/CDN אם קיים.
- למנוע חשבונות מנהל משותפים; לכל מנהל משתמש אישי.
- להפעיל עדכוני אבטחה אוטומטיים/התראות אצל ספק האחסון.
- להגדיר גיבויים ולבדוק שחזור בפועל.
- להגדיר ניטור uptime ושינויים ב-DNS.

מידע רפואי / מרשמים:
האתר הנוכחי אינו מעלה מסמכים לשרת. אם בעתיד תתווסף העלאת מרשם, 29ג, דרכון או מסמך רפואי — אין להפעיל זאת לפני בניית backend מאובטח הכולל לפחות:
- TLS בלבד.
- אימות והרשאות גישה.
- הצפנה במנוחה.
- סריקת malware לקבצים.
- allowlist לסוגי קבצים + בדיקת MIME אמיתית בצד השרת.
- הגבלת גודל וקצב העלאה.
- אחסון קבצים מחוץ ל-web root.
- שמות קבצים אקראיים; ללא שימוש בשם המקורי כמזהה אחסון.
- לוגים ובקרת גישה ללא כתיבת מידע רפואי רגיש ללוג.
- מדיניות שמירה ומחיקה מוגדרת.
- הגנת CSRF, validation בצד השרת, rate limiting ו-bot protection.
- בחינת דרישות הגנת הפרטיות והדין הישראלי הרלוונטי על ידי הגורם המשפטי/אבטחת מידע של הארגון.

הערה חשובה:
הקבצים בחבילה הם baseline טכני חזק לאתר סטטי. הגנה מלאה תלויה גם בספק האחסון, DNS, חשבונות הניהול, תהליכי הארגון וכל backend שיוסף בעתיד.
